# 农村集市摊位抽签收费食品留样与投诉平台

面向乡镇集市的一体化管理平台，覆盖 **报名 → 审核 → 抽签 → 缴费 → 入场核验 → 巡查 → 食品留样 → 投诉处理 → 信用与调整追溯 → 复盘看板** 全链路。

- 后端：Spring Boot 3 + Spring Security(JWT) + Spring Data JPA
- 前端：Vue 3 + Vite + Element Plus + ECharts
- 数据库：PostgreSQL

## 角色与功能

| 角色 | 功能 |
| --- | --- |
| 摊主 VENDOR | 赶集日前报名（品类/车辆尺寸/用电/是否熟食活禽/证照照片/历史经营记录）、查看抽签结果与入场码、缴费、上传食品留样（照片/批次/保存位置）、**查看送检单与检测结果、响应同批次管控（确认下架/登记购买者销售名单）、查看熟食售卖暂停与抽签资格冻结记录**、查看信用与调整记录、提交申诉（费用/扣罚/边界争议） |
| 市场工作人员 STAFF | 扫码入场核验并拍摄摊位布置、登记实际品类与是否按位摆摊、巡查登记（卫生/明码标价/缺斤少两/占道/用电安全） |
| 乡镇管理员 ADMIN | 集市与摊位区域管理、报名审核、组织抽签（种子+规则快照留档、一键复核）、投诉处理（**案件自动关联摊主留样/购买时间/支付凭证/同批次消费者/巡查记录/入场核验/保证金缴费，可发起留样送检**）、**留样送检全流程（抽样送机构→录入结果，不合格自动联动保证金扣罚/信用扣分/暂停熟食售卖/冻结后续熟食抽签资格）**、**熟食售卖暂停与抽签资格管理（可人工解除）**、调整（临时调位/雨天调位/费用减免/保证金扣罚/信用调整/品类变更，原因与来源必填）、复盘看板（高投诉品类/拥堵区域/收费到账/食品安全风险与送检统计）、审计日志 |
| 消费者（免登录） | 凭摊位号提交投诉（腹泻/价格/缺斤少两等），**食品安全投诉可填食品名称、购买时间、包装批次并上传支付凭证截图** |

## 公平与可追溯设计

1. **抽签可复核**：抽签算法为确定性算法——同一「输入快照 + 随机种子」重放结果必然一致。每次抽签固化规则快照与输入快照，管理端提供「复核」按钮重新演算比对，防止结果被篡改。
2. **规则内置**：老摊主（历史经营≥3次且信用≥60）优先；熟食仅入冷链区（有电源）；活禽仅入隔离区；用电需求仅配有电源摊位；车辆超限排除；消防通道等停用摊位不参与分配。
3. **调整必留痕**：临时调位、费用减免、保证金扣罚、信用调整、品类变更均必须填写**原因**与**来源**（雨天/投诉/巡查/争议/摊主申请/政策/留样送检），生成 Adjustment 记录并写审计日志，摊主端可见，避免"规则被人为改变"的质疑。
4. **食品投诉可送检、结果必联动**：腹泻等食品安全投诉可填写购买时间/支付凭证/批次/食品名；管理端案件页自动关联摊主留样、同批次其他消费者（按批次/食品名/购买时间匹配）、巡查记录、入场核验与保证金缴费。管理员可发起**留样送检**并选择同批次管控方式：① 要求立即下架；② 继续售卖但必须留存购买者名单，摊主在线确认下架或提交销售名单。检测**不合格**自动执行保证金扣罚、信用扣分、暂停熟食售卖、冻结后续熟食摊位抽签资格，全部生成 Adjustment（原因+来源=留样送检单号）并写审计；**合格**自动解除调查期间的临时管控。
5. **抽签资格联动**：熟食售卖暂停期内摊主不可报名熟食/凉菜类品类；抽签资格冻结期内可报名但抽签时被标记为 `BLOCKED 资格受限`（记录受限原因，不参与分配，规则快照已升级 v1.1），冻结到期后自动恢复；资格拦截发生在确定性算法之前，不影响历史抽签复核。
6. **全链路审计**：抽签、审核、核验、巡查、投诉处理、送检发起/送样/结果、管控措施、调整等敏感操作全部写入审计日志。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

- 前端：http://localhost （80 端口）
- 后端：http://localhost:8080
- 数据库：PostgreSQL localhost:5432（market / market123）

首次启动自动建表并初始化演示数据（账号、区域摊位、一个报名中的集市）。

## 本地开发

```bash
# 1. 准备 PostgreSQL（建库 market，用户 market/market123），或用 docker 单起数据库：
docker run -d --name market-db -p 5432:5432 \
  -e POSTGRES_DB=market -e POSTGRES_USER=market -e POSTGRES_PASSWORD=market123 postgres:16-alpine

# 2. 后端（默认连 localhost:5432/market，可用 DB_URL/DB_USER/DB_PASSWORD 覆盖）
cd backend && mvn spring-boot:run

# 3. 前端（Vite 代理 /api 与 /files 到 8080）
cd frontend && npm install && npm run dev   # http://localhost:5173
```

## 本题验证方式（完整业务闭环）

1. **报名**：用 vendor1~vendor6 登录 →「摊位报名」选择"十月十五大集"提交（品类/车辆/用电/熟食活禽/证照照片/历史记录）。
2. **审核**：admin 登录 →「集市与报名审核」→ 报名审核 → 全部通过。
3. **抽签**：admin → 集市列表"截止报名"→"组织抽签"输入种子执行；「抽签管理」查看结果明细与规则/输入快照，点"复核"应显示**复核通过**。
4. **缴费**：各中签摊主（vendor1~vendor6）→「抽签结果与缴费」查看摊位号/入场时间/收费项目/保证金/禁止事项/入场码，缴纳全部费用（后续送检扣保证金需要保证金已缴）。
5. **入场核验**：staff1 →「入场核验」输入摊主入场码 → 确认实际品类、按位摆摊、上传布置照片。
6. **巡查**：staff1 →「巡查登记」对摊位登记卫生评分、明码标价、缺斤少两、占道、用电安全。
7. **留样**：vendor1（熟食）→「食品留样」上传留样照片、批次、保存位置；vendor6（孙六·凉菜）上传"凉拌黄瓜"留样（批次如 20261015-01），vendor2（李大嫂·糕点）上传"绿豆糕"留样，供后续送检演示。
8. **投诉与案件关联**：访问 /complaint（免登录）凭摊位号提交"腹泻"投诉，填写食品名（凉拌黄瓜）、购买时间、批次并上传支付凭证截图；可再用另一称呼提交同批次投诉。admin →「投诉处理」→"案件关联"查看自动关联的摊主留样、支付凭证、同批次消费者、巡查与入场核验、保证金缴费记录。
9. **留样送检与同批次管控**：admin 在案件抽屉点"发起留样送检"，选择留样（凉拌黄瓜/批次），管控方式选"要求立即下架"，可勾选调查期间暂停熟食售卖 3 天。vendor6（孙六·凉菜）登录 →「送检与管控」看到红色管控要求 →"确认已下架"；若管控方式为"留存销售名单"，则在线登记购买者姓名/电话/数量/时间后提交。
10. **检测结果联动**：admin →「留样送检」对送检单"登记抽样并送检测机构"→"录入：检测不合格"，填写结果与扣罚（如保证金 ¥200、信用 -20、暂停熟食售卖 30 天、冻结熟食抽签 90 天）。vendor6 →「信用与追溯」可见保证金扣罚、信用调整、暂停售卖、冻结抽签 4 条调整记录（原因+来源=留样送检单号）；「送检与管控」可见生效中的限制。
11. **抽签资格联动**：对暂停期内的新集市，vendor6 报名凉菜被拒绝并提示暂停截止日；对冻结期内的新集市，vendor6 可报名，admin 组织抽签后其报名被标记为"资格受限（BLOCKED）"不参与分配，抽签备注显示"食品安全资格拦截 N 家"，点"复核"仍显示**复核通过**；果蔬等非熟食摊主与冻结到期后的凉菜摊主抽签不受影响。
12. **合格解除（反向验证）**：对糕点摊主送检并选择"留存销售名单"，摊主提交销售名单后录入"检测合格"，系统自动解除调查期间暂停、留样恢复在售；管理端送检单详情可查看摊主提交的销售名单。
13. **调整追溯**：admin →「调整与追溯」发起雨天调位/费用减免/保证金扣罚/信用调整（原因+来源必填）；vendor1 →「信用与追溯」可见全部调整的原因与来源。
14. **复盘**：admin →「复盘看板」查看高投诉品类、拥堵/占道区域、收费到账、食品安全风险（含送检份数/检测中/不合格/暂停售卖/冻结抽签摊主数）；「审计日志」查看全部敏感操作留痕。

## 已执行的验证结论

### 本轮（食品投诉与留样送检功能）

- `mvn test` 全量 **8 个测试通过**：原 6 个抽签算法单元测试 + 新增 2 个基于 H2 内存库（`FoodSafetyFlowTest`，真实启动 Web 容器走 HTTP/JWT/建表）的端到端场景测试：

  2. **合格解除场景**：糕点摊主送检（留存销售名单模式）→ 摊主提交购买者名单 → 录入合格 → 断言调查期临时暂停已解除（无 ACTIVE 记录）、留样恢复 `ON_SALE`、管理端送检详情可见销售名单。
  - 安全断言：未登录访问 `/api/admin/lab-tests` 返回 403。
- `npm run build` 前端构建通过（318 模块）；`vite preview` 实测 `/` 与新增 SPA 路由 `/food-control` 均返回 200。
- 注：本沙箱无 docker、本机 PostgreSQL 超级用户不可用，故端到端采用 H2(PostgreSQL 兼容模式) 验证；实体均为标准 JPA 注解，docker-compose 使用的 PostgreSQL 16 为默认目标库，历史轮次已在 PostgreSQL 15 实测启动。

    └── src/views/
