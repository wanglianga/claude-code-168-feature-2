# 农村集市摊位抽签收费食品留样与投诉平台

面向乡镇集市的一体化管理平台，覆盖 **报名 → 审核 → 抽签 → 缴费 → 入场核验 → 巡查 → 食品留样 → 投诉处理 → 信用与调整追溯 → 复盘看板** 全链路。

- 后端：Spring Boot 3 + Spring Security(JWT) + Spring Data JPA
- 前端：Vue 3 + Vite + Element Plus + ECharts
- 数据库：PostgreSQL

## 角色与功能

| 角色 | 功能 |
| --- | --- |
| 摊主 VENDOR | 赶集日前报名（品类/车辆尺寸/用电/是否熟食活禽/证照照片/历史经营记录）、查看抽签结果与入场码、缴费、上传食品留样（照片/批次/保存位置）、**送检期间按要求对同批次食品下架或留存销售名单并提交回执、查看熟食售卖暂停与熟食抽签资格限制**、查看信用与调整记录、提交申诉（费用/扣罚/边界争议） |
| 市场工作人员 STAFF | 扫码入场核验并拍摄摊位布置、登记实际品类与是否按位摆摊、巡查登记（卫生/明码标价/缺斤少两/占道/用电安全）、**核验时可见摊主熟食售卖暂停/熟食抽签资格取消标记** |
| 乡镇管理员 ADMIN | 集市与摊位区域管理、报名审核、组织抽签（种子+规则快照留档、一键复核）、投诉处理（可联动信用扣分）、**食品投诉溯源（关联摊主留样/购买时间/支付凭证/同批次消费者/巡查记录/保证金）与留样送检（暂停熟食售卖、要求同批次下架或留存名单、登记检测结果并联动保证金扣罚/信用扣分/后续熟食摊位抽签资格、整改后解除暂停）**、调整（临时调位/雨天调位/费用减免/保证金扣罚/信用调整/品类变更，原因与来源必填）、复盘看板（高投诉品类/拥堵区域/收费到账/食品安全风险含送检）、审计日志 |
| 消费者（免登录） | 凭摊位号提交投诉（腹泻/价格/缺斤少两等），**腹泻等食品安全投诉可填写购买时间、上传支付凭证，用于锁定同批次留样与同批次消费者** |

## 公平与可追溯设计

1. **抽签可复核**：抽签算法为确定性算法——同一「输入快照 + 随机种子」重放结果必然一致。每次抽签固化规则快照与输入快照，管理端提供「复核」按钮重新演算比对，防止结果被篡改。
2. **规则内置**：老摊主（历史经营≥3次且信用≥60）优先；熟食仅入冷链区（有电源）；活禽仅入隔离区；用电需求仅配有电源摊位；车辆超限排除；消防通道等停用摊位不参与分配。
3. **调整必留痕**：临时调位、费用减免、保证金扣罚、信用调整、品类变更均必须填写**原因**与**来源**（雨天/投诉/巡查/争议/摊主申请/政策），生成 Adjustment 记录并写审计日志，摊主端可见，避免"规则被人为改变"的质疑。
4. **食品送检全程留痕且影响可追溯**：腹泻等食品安全投诉受理后，平台按消费者**购买时间**与 48 小时留样规定关联摊主**留样批次**、**支付凭证**、**同批次其他消费者**、**巡查记录**与**保证金账单**。管理员发起留样送检后，送检期间**暂停该摊主熟食售卖**，并要求对同批次食品**下架**或**留存销售名单**（摊主须在线提交处置回执）；检测**不合格**自动联动**保证金扣罚 + 信用扣分 + 取消后续熟食冷链摊位抽签资格**（可设期限），检测**合格**自动解除暂停且不作处罚。送检、回执、结果、解除暂停全部写审计日志。
5. **抽签资格限制进入算法快照**：因检测不合格被取消熟食抽签资格的摊主，其 `cookedDisqualified` 标记作为抽签**输入快照**的一部分固化（规则版本升至 1.1），抽签时不为其分配冷链熟食摊位，且任何人可用「复核」按钮按相同快照与种子重放验证，资格限制不会被人为绕过。
6. **全链路审计**：抽签、审核、核验、巡查、投诉处理、留样送检、调整等敏感操作全部写入审计日志。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

- 前端：http://localhost （80 端口）
- 后端：http://localhost:8080
- 数据库：PostgreSQL localhost:5432（market / market123）

首次启动自动建表并初始化演示数据（账号、区域摊位、一个报名中的集市）。

## 本地开发

```bash
# 1. 准备 PostgreSQL（建库 market，用户 market/market123），或用 docker 单起数据库：
docker run -d --name market-db -p 5432:5432 \
  -e POSTGRES_DB=market -e POSTGRES_USER=market -e POSTGRES_PASSWORD=market123 postgres:16-alpine

# 2. 后端（默认连 localhost:5432/market，可用 DB_URL/DB_USER/DB_PASSWORD 覆盖）
cd backend && mvn spring-boot:run

# 3. 前端（Vite 代理 /api 与 /files 到 8080）
cd frontend && npm install && npm run dev   # http://localhost:5173
```

## 本题验证方式（完整业务闭环）

1. **报名**：用 vendor1~vendor6 登录 →「摊位报名」选择"十月十五大集"提交（品类/车辆/用电/熟食活禽/证照照片/历史记录）。
2. **审核**：admin 登录 →「集市与报名审核」→ 报名审核 → 全部通过。
3. **抽签**：admin → 集市列表"截止报名"→"组织抽签"输入种子执行；「抽签管理」查看结果明细与规则/输入快照，点"复核"应显示**复核通过**。
4. **缴费**：vendor1 →「抽签结果与缴费」查看摊位号/入场时间/收费项目/保证金/禁止事项/入场码，缴纳费用。
5. **入场核验**：staff1 →「入场核验」输入摊主入场码 → 确认实际品类、按位摆摊、上传布置照片。
6. **巡查**：staff1 →「巡查登记」对摊位登记卫生评分、明码标价、缺斤少两、占道、用电安全。
7. **留样**：vendor1（熟食）→「食品留样」上传留样照片、批次、保存位置。
8. **投诉与溯源送检（食品闭环）**：
   1. 访问 /complaint（免登录）凭 vendor1 摊位号提交"腹泻/食品安全"投诉，**填写购买时间、上传支付凭证**（建议再用另一名消费者对同摊位提交一条带购买时间的腹泻投诉，用于验证同批次聚合）。
   2. admin →「投诉处理」→ 该投诉行点「**溯源送检**」：抽屉内可查看按购买时间 48 小时圈定的**相关留样批次**、支付凭证、**同批次其他消费者**、巡查记录、保证金账单；选择送检批次，填写承检机构，选择「要求立即下架停售」或「留存同批次销售名单」，开启「暂停熟食售卖」，**发起送检**。
   3. vendor1 →「食品留样」→ 底部「我的留样送检单」可见熟食暂停告警与处置要求，**提交处置回执**（已下架 / 已留存名单）。
   4. 工作人员 staff1 →「入场核验」可见该摊主「暂停熟食」红色标记。
   5. admin →「**留样送检**」→「登记结果」：选择「检测不合格」，可勾选**扣罚保证金**、填写**信用扣分**、开启**取消熟食抽签资格**（可留空=永久或选截止日期），提交；在列表对整改完成的摊点点「解除暂停」。
   6. vendor1 →「信用与追溯」可看到保证金扣罚调整（原因+来源=投诉）、信用扣分流水；首页可见熟食暂停/抽签资格取消提醒。
   7. **抽签资格联动验证**：admin 将"十月廿九大集"改为报名中，vendor1 仍以熟食报名、vendor6 以凉菜报名，审核→截止→抽签→复核：vendor1 因熟食资格被取消而**未中签(LOST)**，vendor6 正常分入冷链区。
9. **调整追溯**：admin →「调整与追溯」发起雨天调位/费用减免/保证金扣罚/信用调整（原因+来源必填）；vendor1 →「信用与追溯」可见全部调整的原因与来源。
10. **复盘**：admin →「复盘看板」查看高投诉品类、拥堵/占道区域、收费到账、食品安全风险（含**送检起数、合格/不合格、暂停熟食与取消熟食抽签家数**）；「审计日志」可查到 `INSPECTION_CREATE/RECEIPT/RESULT/LIFT` 等留痕。
